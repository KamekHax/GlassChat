The text-chat foundation

In source

GlassChat-owned account flow

Email/password registration, Argon2id password hashing, verification and recovery tokens, revocable SQL sessions, and backend permission checks. Email tokens are currently pasted into the desktop form.

One seeded community and one text channel, with member-scoped history, session-authenticated live messages, presence and typing.

Work needed before public service and releases

Not deployed

Central service operations

PostgreSQL, HTTPS reverse proxy, SMTP, monitoring, backups, restore drills, production settings and a public service URL have not been provisioned.

Not verified

Native Windows and security review

Install, first launch, shortcuts, 1.0.0-to-1.0.1 upgrade, data preservation, downgrade refusal and uninstall remain to be tested on clean Windows 10/11 systems. External security and abuse reviews are also open.

Not enabled

Signing and automatic updates

There is no Authenticode certificate, signed production installer, update client or update feed. Future automatic updates require signed releases and a verified HTTPS feed.

Planned, not available

Later milestones

The existing roadmap lists these as future work; no feature should be treated as released until it is implemented and tested.

Planned

Voice, video and screen sharing

WebRTC, signaling, STUN/TURN, device controls, reconnect behavior and a tested network/OS matrix come before any media claim.

Separate architecture decision

Local-first history and E2EE

The current Beta stores channel message text centrally in plaintext at the application layer. Local-first history and client-side encryption are not implemented and require a separately designed data plane.
