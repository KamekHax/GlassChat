Help, not guesswork

Support and bug reporting.

GlassChat does not have a published support email or staffed help desk. The project issue tracker is the current public route for ordinary product questions and non-sensitive bugs.

Project support

Tell us what happened.

Before reporting a bug, check the current documentation and release status. The current central chat service is not deployed; login failures in the public installer candidate are expected.

Open a GitHub issue ↗

Include useful context

  • GlassChat version and build ID, from the About/footer or installer properties.
  • Windows version and whether you used setup or a portable build.
  • Steps to reproduce and the exact sanitized error message.
  • Whether the issue affects a published release or an unpublished development candidate.

Do not include passwords, session tokens, verification or reset tokens, private message content or database credentials.

Security issue? Do not post exploit details, credentials or sensitive user data in a public issue. A private security-reporting channel has not yet been configured. See the security page for the current limitation and responsible-disclosure guidance.
