Product

What GlassChat is

GlassChat is an independent Windows-oriented desktop chat Beta with its own email/password account system and a Liquid Glass-inspired interface. The backend is designed to be centrally operated so community members do not run their own servers. The public service and user-facing web account pages are not deployed.

Today, the application source implements one seeded Commons community and a #general text channel. It is a narrow foundation, not a complete Discord replacement.

Windows

Installation and first launch

The project has a Windows x64 NSIS setup candidate and a portable candidate at version 1.0.1, build 20261031.1. Neither is currently a published GitHub Release. The installer is unsigned, and native Windows installation, first launch, shortcuts, update, data-preservation and uninstall tests remain outstanding.

The packaged client defaults to a local development service URL. It cannot sign in or chat over the internet until the GlassChat HTTPS service is deployed and the correct service URL is configured. Follow the Downloads page for verified availability; this site will not link the local candidate.

The setup is designed for a per-user Windows install and bundles its desktop runtime. Users should not need to install Node.js or developer tools, but those installer behaviors have not yet been validated on native Windows.

Identity

Account registration, login and recovery

In source, GlassChat owns its email/password authentication. PostgreSQL stores account/session data; passwords are hashed with Argon2id, and opaque sessions are revocable. The application does not use ManusAI authentication. This backend is not publicly deployed, so account creation and sign-in are not currently open to website visitors.

The implemented account flow includes registration, email-verification resend, login, password-reset requests and logout. Verification and recovery emails deliver single-use tokens; the desktop forms currently require the user to copy and paste a token. There is no hosted web landing page or deep-link handler.

Text chat

Messaging and direct messages

Members of the seeded Commons community can join #general, view membership-scoped recent channel history, send text messages and see online presence and typing status when connected to a deployed service.

Direct messages are not implemented. Friends, requests, group messages, search, attachments, reactions, replies, message edits/deletes, pins, mentions, notifications and read receipts are also unavailable. A disabled or absent control should not be interpreted as an available feature.

Channels

Communities, channels and permissions

Every newly registered account is enrolled in the seeded Commons community. In the current slice there is one general channel. The backend checks community membership before listing history or joining and sending messages. Socket messages derive their author from the authenticated session, not from a client-chosen name.

Community creation, switching, channel administration, role management UI, invites, moderation, blocks, reports and account deletion are not implemented. Member/admin database scaffolding is not a user-facing permission system.

Not available

Voice, video and screen sharing

GlassChat does not currently implement voice calls, video calls, screen sharing or WebRTC. There are no working controls or deployment claims for these features. See the roadmap for planned work and its testing gates.

Not available

Profiles and customisation

Profiles, custom statuses, user-controlled privacy settings and profile uploads are not implemented. The current client displays the account username and generated initials only.

Not available

Bots and integrations

There is no bot API, integration marketplace, webhook product or user-installable bot system in the current Beta.

Read before use

Privacy and security

The current Beta is not local-first and does not provide end-to-end encryption. Channel message text is stored in the central PostgreSQL database in plaintext at the application layer; the service and database operator can read it. HTTPS/WSS protects data in transit, not server-side message content. Do not use GlassChat Beta for private or sensitive conversations.

Electron keeps the session in its main process and uses operating-system encryption through safeStorage when available. If operating-system encryption is unavailable, the current process keeps the session in memory only and signing in again may be necessary. No production service, external security audit or complete threat review has passed.

See the security status and the clearly marked privacy draft.

Help

Troubleshooting and frequently asked questions

Why can’t I register or sign in?

No public GlassChat account service is deployed yet. The desktop Beta requires a reachable GlassChat API, configured with HTTPS outside local development.

Where is my chat history stored?

In the current Beta, channel messages are stored on the central service, not only on the user's device. There is no local conversation-history database or end-to-end encryption.

Can I message a friend or start a voice call?

No. Direct messages, friends, voice, video and screen sharing are not implemented.

Is the Windows installer verified?

The 1.0.1 candidate is unsigned and has not passed native Windows lifecycle tests. Check the release page; only published releases appear there.

Where can I report a regular bug?

Use the GlassChat GitHub issue tracker for non-sensitive bugs. Do not post security-sensitive vulnerability details publicly.
