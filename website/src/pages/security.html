Read before using the Beta

Security status and boundaries.

This page describes the current source architecture and its open deployment/review gaps. It is not a certification, a third-party audit, or a promise that the central service is ready for public use.

Do not use this Beta for sensitive conversations. Channel messages are stored centrally in PostgreSQL as plaintext at the application layer. The current app has no end-to-end encryption and does not keep the authoritative conversation history only on the user's device.
Implemented in source

Independent account security

GlassChat-owned SQL authentication; Argon2id password hashing; one-use verification and reset tokens; opaque revocable sessions; server-side community membership checks; request rate limits; CSRF protection on protected HTTP requests.

Implemented in source

Desktop session boundary

The Electron main process owns the session token. The renderer receives a narrow IPC surface; operating-system encrypted storage is used when available. No password hash or database credential is sent to the client.

Not production-ready

Service and release gates

The central API is not publicly deployed. The Windows candidate is unsigned; native Windows lifecycle checks and external security review are outstanding. Automatic updates are disabled. Gmail API OAuth delivery is implemented in source but has not been configured or tested against a live mailbox.

Known architecture

What the current design does not guarantee

HTTPS/WSS protects data while it travels to the service; it does not encrypt message content from the server operator.

There is no local-first authoritative message-history store, no client-side end-to-end encryption protocol, no public production account service, and no independent penetration test.

Do not publish account credentials, private conversations, reset links, session secrets or database details in issues or screenshots.

Responsible reporting

How to report a vulnerability

Send a private initial report to kamekfnbr@gmail.com. This is the operator-approved contact address; do not include passwords, access tokens, reset links or private message contents.

  1. Do not disclose a suspected vulnerability, exploit steps, secrets or user data in a public issue.
  2. A temporary central GlassChat API is deployed for invited testing. Do not probe, scan or test it—or any third-party or production system—without explicit authorization from the operator.
  3. Provide a concise description and safe reproduction details. Coordinate further disclosure privately.
  4. For ordinary, non-sensitive product bugs only, use the public issue tracker ↗.

No response-time, remediation-time or bounty commitment is made.
